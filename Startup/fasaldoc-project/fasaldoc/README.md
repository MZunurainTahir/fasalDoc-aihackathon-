## Full Local Run (end-to-end, in order)

### 1. Train the model (once you have a dataset)
```bash
# In Google Colab or locally with a GPU:
python train_baseline_model.py
# Produces: fasaldoc_model.keras, fasaldoc_model.tflite
```
After training, also save the class names your training script generated:
```python
import json
json.dump(train_ds.class_names, open("class_names.json", "w"))
```

### 2. Fill in the remedy database
Open `remedy_database.json` — it currently has 4 sample entries as a format reference. Your Data Lead should:
- Add one entry per disease class in `class_names.json`
- Get every entry checked by your agronomist/vet advisor before this goes anywhere near a real user
- Keep keys exactly matching the class names (case-sensitive)

### 3. Run the backend

**Option A — Docker (recommended, matches production environment):**
```bash
cd backend
docker compose up --build
```
This starts the API at `http://localhost:8000`. Visit `http://localhost:8000/docs` to test it interactively.

**Option B — Directly with Python (faster iteration while coding):**
```bash
cd backend
python -m venv venv
source venv/bin/activate      # venv\Scripts\activate on Windows
pip install -r requirements.txt
uvicorn main:app --reload
```

### 4. Find your local IP (needed for mobile testing)
```bash
# Mac/Linux:
ifconfig | grep "inet "
# Windows:
ipconfig
```
Look for something like `192.168.x.x`. A physical phone on the same WiFi network needs this address, not `localhost`, to reach your backend.

### 5. Run the mobile app
```bash
cd mobile
npx create-expo-app . --template blank
npx expo install expo-camera expo-image-picker
npx expo install @react-navigation/native @react-navigation/native-stack @react-navigation/bottom-tabs
npx expo install react-native-screens react-native-safe-area-context
npm install @react-native-async-storage/async-storage
```
- Update `API_URL` in `CaptureScreen.js` to `http://<your-local-ip>:8000/predict`
- Run `npx expo start`, scan the QR code with the **Expo Go** app on your phone

### 6. Test the full loop
Phone camera → photo captured → sent to your laptop's backend over WiFi → prediction + remedy returned → displayed on screen. **This is your working MVP.**

## DevOps Notes for Your Backend/DevOps Lead

- **CI pipeline** (`ci.yml`): runs lint + import checks on every push/PR, and confirms the Docker image builds on pushes to `main`. It intentionally does NOT auto-deploy yet — that's a deliberate scope cut for now. Add a deploy job once you've picked a hosting target.
- **Recommended hosting for MVP/pilot stage:** Google Cloud Run — pay-per-request, generous free tier, simple container deploys straight from a Dockerfile (which you already have).
- **Before any public deployment:**
  - Lock down CORS in `main.py` (`allow_origins=["*"]` is fine for development, not for production)
  - Add basic rate-limiting (e.g. `slowapi` package) so the API can't be abused
  - Move any secrets (API keys, DB credentials once you add a database) into environment variables, never hardcoded
- **Model updates:** since the model file is baked into the Docker image, redeploying after retraining means rebuilding and redeploying the image. Fine for MVP; if you need faster model updates later, consider loading the model from cloud storage (e.g. a GCS bucket) at container startup instead.
